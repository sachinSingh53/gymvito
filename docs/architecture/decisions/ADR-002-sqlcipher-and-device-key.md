# ADR-002: SQLCipher and device-key lifecycle

Status: Accepted, native verification pending

`expo-sqlite` is configured with `useSQLCipher: true`. A random 256-bit lowercase-hex key is generated by `expo-crypto` and stored only in SecureStore service `com.gymvito.database-key.v1`, without biometric binding. The key is applied before any database read. An existing database without its key is a recovery error and is never overwritten automatically.

Startup sets foreign keys, a five-second busy timeout, WAL, application ID, migration checksums, and a quick integrity check. User values use bound statements; the fixed-width validated raw device key is the only SQLCipher PRAGMA interpolation.

Android automatic application backup is disabled so the operating system cannot restore an encrypted database without its non-backed-up SecureStore key. User-controlled `.gymvito` files are the migration/recovery path.
